# Astra诊断核对与研究主线调整建议

2026-10-23。对照用户提供的[Astra原文](/home/erzhu419/mine_code/Thesis/markdown/Astra_diagnosis_20261023.md)、原实现与已有小汇总整理。本文补充前一份[项目报告](/home/erzhu419/mine_code/Thesis/experiments/mcwm_closed_loop_progress_review_20261023/PROJECT_STATUS_AND_PROBLEM_REPORT.md)，旧报告、代码、门槛和结果保持原样。本次没有提交新实验。

## 1. 总体判断

Astra指出的研究设计缺口成立：现有工作已证明闭环真实运行，也定位了若干模型响应错误，但“新目标监督相对继续优化带来多少增益”还没有被计算匹配的对照识别。服务反转研究已经提供机制线索，应重新界定为特定特征假说的辅助任务，最终主终点仍是实际乘客成本。

早期动作契约、零时长和fork文件状态等实现问题确实发生过；修复后的负结果不能继续统一归到这些旧问题上。“当前主要瓶颈是设计”是综合判断，尚不等于已分离状态、样本、正则和执行条件的因果份额。

## 2. 对上一份报告需要补充的关键限定

### v23是首次反转预测失败，尚无学过后的再次反转检验

原`training_gate.json.rows`给出的7X时序为：

| issue | 预测时已准入的本线监督 | 第三站真实时差 | shared预测 |
|---|---|---:|---:|
| 1559 bootstrap | 无 | 0秒 | 不支持 |
| 3815 response | 仅bootstrap | −6秒 | +3.785秒 |
| 16243 late | 已含response的−6监督 | +3秒 | 约+0.50秒 |

因此可以说首次负响应没有被预测到；不能将该例写成“提供反转监督后，模型仍再次预测不出反转”。到离站两个−6秒端点来自同一个状态，只有一个反转案例。上一报告的“已有可评分反转而预测错号”应按这个时序理解。

证据：[v23训练门](/home/erzhu419/mine_code/Thesis/experiments/mcwm_closed_loop_stratified_pairs_v23_20261023/training_gate.json)。

### ridge收缩的作用应区分目标单位、输入尺度与先验

当前服务预测代数上为：

\[
\widehat{\Delta t}=7.5+x^T(X^TX+I)^{-1}X^T(\Delta t-7.5).
\]

目标先除60、预测再乘60会抵消；只改目标单位不会改变这份线性ridge的预测。历史输入除60、固定ridge=1，则改变历史列的有效正则强度。正则覆盖三条线路one-hot截距，会把少样本结果向+7.5秒先验收缩。

仅有一个真实0秒样本、只看线路截距时，预测就是`7.5+(0−7.5)/(1+1)=3.75秒`，与实际3.785秒接近。它是估计器设定的结果，不是求解错误。去掉正则是否更好仍需新证据；late时本线历史均值会预测−3秒，真值却为+3秒。

v21加历史后的最大端点改变量0.037708秒；v23为0.043119秒，两者不能跨版混用。它们都说明当前候选的实际作用很小，尚未充分检验一个能产生秒级变化的历史模型。

### 705X选中同层，不代表整个窗口只有一层

采样器在后1/3窗口遇到首个可行状态后回退选中，随后停止考察该cell。response/late仅考察3/4个eligible状态。旧结果确定违反预定覆盖门，停止是正确的；它没有枚举选中后的候选，不能证明全窗口不存在新层。

分层使用第三段残差，history5输入三段均值，两者不是同一统计量。通过分层数量门也不直接证明模型支持充分。

### 执行条件问题尚未结案

F的completion floor在归一时钟[0.15,0.75)，即3600–18000秒启用，还要求前后车、需求和载客条件。7X的1559与3815确实跨边界，实际作用量尚未测定。v19只研究late→tail，未覆盖3600边界；三点没有翻号不意味着未来控制条件无关。

## 4. 应调整的研究计划

**优先补fresh贡献归因。** 在当前统一F下设计同初始化、同运行时长、同57包/456次更新、同真实TD系数、无world的fresh与无fresh监督两臂。旧A1在v3动作统一之前，不能把修复后的新无fresh臂直接减旧A1，声称只改变了fresh。旧A1保留作历史参照；新的主比较应成对运行。

新协议应明确估计对象：保留相同的fresh状态使用规则，仅禁止新结果用于带标签监督，回答新增outcome监督的贡献；若连fresh状态一起删除，回答的是整个fresh数据包的贡献。闭环中各臂轨迹可分化，不能宣称逐条收到相同state/outcome。无fresh监督槽必须用完整既有转移替换，不能把旧reward拼到新state上。

**将主继续条件放回决策效用。** 服务反转用于解释特定状态表示；它不是已证明的总成本改善必要条件，也不充分。新协议应预先规定相对固定0、shared等参照的300秒regret及稳定场景损害，再验证接管控制后的全日成本。旧v21–v23门保持失败，不追溯改判。

**明确数据权限。** v1原方案仅使用事实执行结果；v16起的同前缀双臂训练引入可分叉SUMO反事实查询。285槽正确不代表信息相同。核心事实反馈归因实验不应为了复用9对执行器而引入这些查询；若保留配对训练作为方法组成，所有学习对照必须共享查询权限和预算。

**配对支线先统一条件和支持。** 后续若恢复，明确未来F阶段，采样依据与模型输入对应；在新前缀保存小型候选层计数，区分首次变化预测与获得监督后的重复变化预测。当前资料不足时保留未知，不为补统计重跑旧日，也不调ridge追旧留出。
