**v23 的结果，需要比原报告再细分一层。**

第一，705X 的覆盖失败是确定的，但“整个窗口不存在第二层”尚未确定。源码在窗口最后三分之一遇到首个可行状态就回退；选中后不再继续考察该 cell。response 实际只考察了 3 个 eligible 状态，late 考察了 4 个。现有结果证明的是：**这个采样器拿到的三对属于同一层**，并没有证明回退之后不会出现新层。[采样实现](/home/erzhu419/mine_code/Thesis/experiments/mcwm_closed_loop_stratified_pairs_v23_20261023/sampling.py:64)

原可行性预查主要检查车辆事件能否落入窗口，没有提前验证联合状态层覆盖。因而“能选满九对”与“九对足以支持模型”之间仍有设计缺口。

第二，采样与模型使用的变量并不相同。分层依据是**第三段残差分档**，history5 输入却是**三段残差均值**。第三段跨档，不保证均值能区分不同服务响应；反过来也一样。因此“每线至少两层”可以是预定探索要求，却不能直接当作可识别性证明。

第三，也是最容易误读的一点：**那个真实 −6 秒、预测约 +3.8 秒的反转，并不是模型已经学过反转后的再次失败。**

原始准入顺序是：

1. 1559 秒的 7X bootstrap：第三站真实时差为 **0 秒**。
2. 3815 秒预测 response 时：模型只见过上面这一条训练记录。
3. response 后来揭示第三站真实时差为 **−6 秒**。
4. 到 late 时，模型已经见过 −6 秒，但该状态真实时差为 **+3 秒**，模型预测约 **+0.5 秒**，方向正确。

所以，准确结论是“首次出现的反转没有被预测到”。目前没有第二个后续反转状态，用来检验模型得到反转监督后是否学会了它。[v23 原始时序与预测](/home/erzhu419/mine_code/Thesis/experiments/mcwm_closed_loop_stratified_pairs_v23_20261023/training_gate.json:529)

这仍然暴露了早期预测能力不足，但它削弱了“已经提供反转样本，模型仍然学不会”的归因。

**当前服务模型的正则设定，确实在很大程度上决定了上述预测。**

实现是：

\[
\widehat{\Delta t}
=7.5+x^\top(X^\top X+\lambda I)^{-1}X^\top
(\Delta t-7.5),\qquad \lambda=1.
\]

如果暂只看线路截距，一个真实时差为 0 的样本，加上 ridge=1，就得到：

\[
7.5+\frac{0-7.5}{1+1}=3.75\text{ 秒}.
\]

实际 shared 预测为 3.785 秒，与这个收缩机制非常接近。**这不是求解程序算错，而是小样本、7.5 秒先验和截距正则共同产生的结果。** [拟合实现](/home/erzhu419/mine_code/Thesis/experiments/mcwm_closed_loop_service_shift_v21_20261022/shift_model.py:44)

这里还应纠正一个技术归因：

- **目标除以 60、预测再乘以 60，在当前线性 ridge 中会抵消**；单改目标单位不会改变最终预测。
- **历史输入除以 60，再固定使用 ridge=1**，才会改变历史列的有效正则强度。
- 连线路截距一起正则，则会把少样本预测拉向 7.5 秒先验。

已有 v21 分解显示，加入 history 后，六个留出状态中单端点预测的最大变化不足 **0.038 秒**。这意味着候选在实际数值上几乎没有改变 shared，而不是已经充分检验了“历史状态能否解释秒级反转”。[已有设计分解](/home/erzhu419/mine_code/Thesis/experiments/mcwm_closed_loop_v21_review_20261023/history_design_diagnostic.json:9)

但也不能顺势得出“去掉正则就会成功”：v23 late 的本线历史均值会预测第三站 **−3 秒**，而真值是 **+3 秒**；当前收缩模型反而保住了正确方向。正则同时可能造成偏差和抑制错误外推，不能只看首次反转就决定调小它。

**我最建议调整的，是不要让“预测对服务反转”成为整个第六章必须通过的唯一入口。**

对“这条历史特征能否解释反转”这个具体假说，服务门是合理的。但最终目标是：

\[
G=2\Delta W+\Delta R,
\]

它涉及全系统乘客时间，本车到离站时差只是一个中间量。v20 已经发现，同线其他车和其他线路对收益有实质贡献。

holding 可以通过头距与乘客分配改善等待，而不一定让本车“晚出发却早到达”；反过来，准确预测本车提前，也不保证总乘客成本下降。因此，**服务反转既不是成本改善的充分条件，也没有被证明是必要条件。**

当前按旧门停止 v21–v23，是正确执行；但下一版计划应重新判断这个辅助任务的地位。尤其每线只有两个可评分状态时，把 0.001 秒左右的 MAE 退化直接等同于不值得研究的控制损害，缺少实际效用依据。

接下来，我建议按下面的优先级收敛：

1. **先补第六章最核心的贡献归因。**  
   保留现有 A1，设计同初始化、同 456 次更新、同回放配额但不给 fresh outcome 的对照。主比较用绝对乘客成本，稳定和冲击分别看。如果 A1 仍有稳定优势，才把收益明确归于新增监督；如果没有，应把已有收益解释为继续优化贡献较大。

2. **服务模型暂不再加新特征，也不直接调 ridge 追分。**  
   下一候选首先需要说明：该输入在实际正则设定下能造成多大的预测变化，训练时是否有对应支持，以及变化是否与错误动作损失有关。当前 history5 几乎不改变预测，应先解决这个实验解释问题。

3. **若继续配对路线，先统一下一实验的条件和采样目的。**  
   明确后续 F 的适用阶段；让采样依据与模型真正使用的变量一致；区分“首次反转检测”和“获得监督后的再次反转预测”。705X 全窗口状态层若没有保存足够历史，就承认旧记录无法恢复，不为补这一项重跑旧日；在下一次本来就需要的新前缀中记录小型候选层计数。

4. **将继续条件重新放回决策收益。**  
   服务端点用于解释机制，是否进入下一阶段应最终由同状态下相对固定 0、shared 等参照的 300 秒 regret，以及后续接管控制后的全天成本决定。旧版本门槛保持不变，新协议在运行前确定。
