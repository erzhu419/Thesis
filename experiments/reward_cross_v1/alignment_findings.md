# 车头时距分支的转换与动作对齐核实

## 判断

当前最直接的问题是新时距奖励沿用了乘客目标的全局事件转换，没有对齐RE-SAC的同车站间反馈，而且下一事件状态会丢失此前滞站动作的运行影响。动作不是未执行或发给了错误车辆，脊形奖励公式也没有算错。不能据此认定H2O+或MC-WM不适合时距控制。

## RE-SAC的链条正确

对原项目和博士论文使用的冻结环境，各运行一个完整运营日，给不同车辆、车次和站点选择可区分的0、7、23、60秒动作。原项目共5232次控制动作、4970条入库转换；冻结版本共5233次动作、4971条转换。车辆归属、动作锁存、滞站倒计时、入库动作、奖励事件和奖励公式均没有错配。

原项目的一条实际记录是：车辆2在站点1、时刻422秒返回状态，选择7秒额外滞站；423秒锁存动作，完整执行7秒。该车在站点2、时刻510秒返回奖励−17.99。训练先写入“站点1状态、7秒动作、站点2奖励、站点2状态”，再为站点2选动作。不是用站点2的新动作配站点1的旧状态。

同车复用后，原项目245次、冻结版本243次跨趟衔接被现有站点条件跳过，本次没有跨车次或跨方向的错误入库。未产生控制事件的初始锁存均为零动作。

## H2O+/MC-WM的执行也正确

源仿真实际采集1501次决策，1501次指令全部由对应车辆锁存；已观察到1481次释放，实际滞站倒计时均与指令一致。状态事件的车辆与站点、策略输出到执行器的换算、同批次已选动作的缓存均正确。

SUMO短程追踪188次指令，188次均下发给正确车辆，读取SUMO当前停站参数也与指令一致。180次已观测离站均没有提前于要求的滞站结束。上下客完成到离站比要求时长平均多1.27秒，包含离散步进和释放过程，不是少执行60秒或把基础停站时间重复执行一次。

SUMO这项验证针对最终物理指令。现有策略评估在此之前仍施加原乘客保障变换，源训练则直接执行原始滞站；此前确认的训练与部署动作处理不一致仍成立，但不是执行器把指令发错了车辆。

服务器上分段抽取32768条离线转换；动作取值、线路与站点元数据均正确。10104条同批次转换的决策下标和已选动作缓存全部一致，没有发现动作移位或符号反转。

## 但新奖励没有按同车站间效果结算

源仿真1500条已结算转换中，1497条的下一事件来自不同车辆，1341条来自不同线路。345条在同一批次、物理时间未推进时结算；其中325条得到非零脊形奖励，此时对应动作尚未送入物理仿真。原乘客时间增量在这些行仍为零。

例如时刻1235秒，7S线路车辆2在站点2选择60秒滞站，下一条转换却用7X线路车辆1在站点5的时距给出−596.35。该奖励不是前一辆车执行60秒后的本站或下一站效果。

共享全局奖励可以是合法的另一种控制问题；这里的问题是，它不等价于此前要求复用的同车站间奖励。不能简单把所有零时长奖励清零，那会遗漏同批次其他车辆的真实时距评价。

## 单动作配对扰动

复制同一个源仿真状态并恢复相同随机数状态，只把102S线路车辆1的本次额外滞站从0秒改为60秒，其他车辆动作保持一致。

| 观测 | 0秒 | 60秒 |
| --- | ---: | ---: |
| 同批次下一决策的脊形奖励 | −306.89 | −306.89 |
| 下一物理全局事件时刻 | 4777秒 | 4777秒 |
| 下一物理全局事件脊形奖励 | −389.09 | −389.09 |
| 被控制车辆下一站时刻 | 4832秒 | 4894秒 |
| 被控制车辆下一站前向时距 | 202.5秒 | 264.5秒 |
| 被控制车辆下一站脊形奖励 | −147.37 | −39.60 |

动作确实改变了后续运行，并在这个状态下改善了被控制车辆的时距。但当前一阶反馈没有直接呈现这项改善。同批次下一状态只有前一车辆动作缓存发生变化，时距特征不变。

更关键的是，到达下一物理全局事件时，两分支输入算法的整个229维状态完全相同。底层仿真仍保留不同的车辆运行状态，观察状态却只包含当前事件批次及全系统人数，没有保留此前那辆车尚未完成的滞站影响。相同的观察状态，后续同车时距仍不同。这是实际出现的状态信息丢失，不只是“奖励延迟几十步”。在这个分支点，采用当前状态的单步价值自举不能区分两种历史；仅增加训练步数或调整折扣不能补回缺失的信息。

## 历史双动作版本对照

`3416538`是2026年2月23日的SUMO双动作SAC版本，当时尚无H2Oplus代码树。继续追到H2Oplus公交提交`3f20b4a`，确认以下差异。

- **同车反馈与动作记忆。** 两版均按车辆缓存，下一站结算后才选新动作。旧H2O+使用15维本站观测加2维该车上一动作；当前同批次前序动作缓存不等价。交错车辆小测试全部匹配。本地现有v2文件抽取4096条转换，跨车、跨方向、上一动作错配均为零，819条速度动作非零。
- **控制自由度。** 旧SAC控制0至60秒额外滞站和0.8至1.2速度比例，SUMO用`setSpeedFactor`执行；旧H2O+速度采用五档。当前速度固定1.0，已不是原来的双动作控制问题。
- **速度响应。** 当前经验运行时间标定分支绕过速度比例。500米、标定100秒的固定区间测试中，0.8与1.2速度动作在旧机制分支首次推进8与12米，当前分支均推进5米，均在100步后走完。现有单动作约定正确，但解禁速度必须同时修改源仿真。
- **奖励与数值。** 旧版是前后偏差的tanh附加惩罚之和取非负部分，当前是任一偏差越阈即扣20。计划间隔360秒、前后时距545与360秒时，分别约−277.50与−297.50。旧SAC逐批奖励标准化乘10、折扣0.99；旧H2O+固定离线统计标准化乘10、折扣0.80。当前乘0.01、非终止折扣1。旧版熵温度初值约0.1、上限0.6，不能只复制奖励而忽略学习尺度。

这些证据支持优先修正反馈接口，不支持继续盲目增加训练量。测试脚本为`compare_historical.py`，小型结果为`historical_comparison.json`。

## 下一步

先建立独立的同车站间时距分支：离线按运营轨迹、线路和车辆找到该车的下一控制事件；在线按车辆保存待结算动作，到同车下一站结算。车次边界单独处理，不能跨运营日拼接；其他车辆的期间动作作为环境运行的一部分。

第一组重组当前单动作数据，补回该车上一动作，单独判断反馈修正的效果。第二组建立独立双动作接口，为标定模型加入速度可控的行驶分量，匹配离线采集、源仿真与SUMO的速度映射。不能直接删掉旧v2数据的速度维度作为单动作数据。两组的H2O+和MC-WM均使用组内相同动作空间。

在相应反馈接口上重新拟合世界模型，合成奖励由预测下一状态的脊形函数解析计算，避免独立奖励头与预测时距互不一致。训练与部署使用一致的额外滞站处理，先测试不带原乘客保障处理的策略，再单独比较保障后的表现。反馈修正后再比较奖励缩放，不先靠增加种子或训练时长掩盖接口问题。

## 范围

这是执行与反馈链条诊断，不是修正后训练结果。配对扰动只证明一个实际状态下的即时反馈不敏感、同车后续效果不同，尚未测定该因素对最终性能退化的贡献。观察状态压缩由两种目标共用；原乘客目标的已有经验收益继续保留，但这些收益不能证明观察状态严格满足马尔可夫性。没有修改原论文项目、训练权重、CFCMT或博士论文正文，也没有派发新一轮正式训练。

历史速度测试是固定区间机制测试，不是运营效果对照；本地v2文件尚未认定为2026年2月原训练所用的同一份数据。提交说明和源码注释中的收益没有当作本轮核实的实验结果。

历史代码也不能整套回退：桥接在上下客完成后仍加入基础停站，应保留当前仅下发额外滞站的做法；旧H2O+每步两次增加累计距离，实测推进8、12米却累计16、24米，当前已经没有这个错误；旧SAC包含物理动作雅可比、旧H2O+使用原始动作密度，目标熵常数不能直接照搬。

追踪脚本为本目录的`trace_alignment.py`；四份`alignment_*.json`保存原始小型记录。历史对照脚本为`compare_historical.py`，结果为`historical_comparison.json`。服务器数据与权重没有整批拉回本地。
