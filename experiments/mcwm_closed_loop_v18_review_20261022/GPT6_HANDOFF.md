# 公交MC-WM v18：问题、结果与代码说明（2026-10-22）

**四日、48个留出分支和72个训练子分支全部完成。新增载客项不推进独立确认：总体方向正确数15/24不变，regret从1171增至1379（+208）。** 下面材料供GPT6分析后续方案；本轮没有提交新候选、独立确认或部署。

## 研究问题和本版唯一改动

我们希望MC-WM利用fresh target online dripping data适应公交环境，并让预测改善传到动作价值和实际控制。v17已缩短配对标签年龄、补齐三线两窗，但真实300秒响应在12组跨窗口中有8组翻号，原低维模型还有三处预测跨零。v18先只读诊断既有60个配对状态，再固定一个改动，用新共同前缀验证。

原低维shared以三条线路截距和一个前后头距偏差差值，分别拟合等待、乘车的300秒动作差分。v18 candidate的等待输出逐值保持shared，乘车输出仅多一列issue时的当前车内载客数/容量；线路常数route、低维shared和固定0秒zero全部保留。ridge=1、目标缩放1000不变，不用旧留出数据拟合或选择超参数。

初始化仍为6201/6202对应的50,000次训练checkpoint，history32768/source4096；新目标外生种子84201/84202，稳定/局部速度冲击两场景，目标时长24000秒。物理基线仍用102个source区间，不新增target物理标签，trust公式保持。每个动作兄弟分支重放相同前缀和外生种子，仅在诊断issue执行0或7.5秒。

```text
共同action_model控制流 → 延迟反馈包 → 原策略/world/trust更新
                          ├─ 267条普通标签/日
                          └─ 9个配对×2动作标签/日
                              → route / shared / candidate同标签被动拟合
停更后同一留出状态 → 0/7.5秒原生冻结分支 → 真实300秒收益与选动作regret
```

需要区分的数据通路：**285条反馈更新共同流，但差分读出每日只用9个已准入配对差分；267条普通标签不直接拟合这些读出。** 最后反馈包在18000秒左右执行，留出窗为[18010,18700)、[18700,20000)，后缀不训练。candidate未接管日常控制，因此本次比较的是原生配对动作诊断，四路不能各自声称全日成本改善。

统一收益`G=C(0)-C(7.5)`，`C=2×等待人秒+乘车人秒`。G正选择7.5秒，否则选0；regret为该选择相对两动作真值最优的额外加权乘客人秒，表中报告同一状态集合的regret总和。

## 两次动作跨零解释全部变化

1. 6202冲击7X窗口2：真G=-84，shared预测+1.367，candidate变为-5.213，减少regret84。
2. 6202冲击705X窗口1：真G=+292，shared预测+9.104，candidate变为-11.671，增加regret292。该点载客47人，在本线训练范围内。

7X有益点真实为`(4,-92,-84)`，shared为`(-61.565,+124.497,+1.367)`，candidate为`(-61.565,+117.917,-5.213)`。candidate乘车预测仍错号，却让合成成本跨回正确方向。这也不能解释成已经学对乘车机制。

24态等待预测全部精确不变，成本收益预测23态下移。四日载客系数均负，ride设计均rank5，未见数值秩亏。12组跨窗仍有8组真实翻号；shared预测3组翻号，其中1组与真实相符，candidate仅预测1组且为假翻号。详见[机制复算](mechanism.json)。

补充事后敏感性诊断：只把candidate的等待输出替换为留出真值，regret1379→725；只替换乘车输出，反升到2041。它不新增训练、不是可部署模型或性能上界，只说明即使单头更准，联合成本仍可能更坏；这不足以单独选定下一版结构。

## 外推、缺失、不支持和零时长

v18四日7X训练载客均为3–5人，留出两个窗口为13/1人，8态全部超本线范围；102X/705X共16态均在本线范围内。坏结果发生在范围内705X，不能只归因于外推或通过删除外推样本解决。

24留出状态全部选中、三类端点完整，四路均支持，无缺失；训练issue时三学习器各有12/36冷启动不支持（各日各线首对），不能用后来的标签补齐或混入留出支持率。

global零时长：训练8/36对，占16标签槽，照常监督固定300秒响应，按原规则不进正时长world/trust拟合。留出2/24态均为102X冲击窗口2，真实G为-80、-25；shared/candidate均1/2方向正确、regret25。剔除这2态后两者14/22正确，regret1146→1354，仍增加208。零时长不等于300秒零效应。

## 给GPT6的问题与下一步决策

本版不晋级独立确认、不改trust、不提交下一批正式实验，后续任务仍high。已有证据要求解释的是“等待/乘车差分误差如何合成动作价值”，不能仅用单头MAE下降作为晋级依据。请GPT6据代码与数据独立判断：

- 主要限制更接近等待/后续服务响应缺失、有限配对下的状态可识别性，还是分头目标与合成动作收益不一致？现有数据能区分哪些解释？
- 在保持285预算、配对每对2名额、物理基线和trust不变时，下一项最小且可检验的结构或目标改动是什么？应先用已有数据做什么诊断，再用什么新前缀、覆盖和停更验证判定？
- 如何评价两个近零预测点的动作变化，避免只在当前24态上调符号、挑线路或挑窗口？

限制：仅2个初始化/外生种子、4条共同日流；24状态不是24个独立训练重复。四路被动共享主日成本，不能据此报告candidate全日控制退化或恢复。v17/v18外生种子不同，跨版本绝对指标差不代表载客项效果，正式比较必须用本版同流shared/candidate。
