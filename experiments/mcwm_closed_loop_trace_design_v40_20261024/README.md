# v40：已知随机执行行为与285槽连续反馈设计

当前仅设计和服务器旧日志预检：新增原生前缀、分支、训练标签及优化器更新均0，不读取诊断真值作训练，不自动启动后续采集。旧版本和旧结果只读，任务优先级high。

行为固定为原50000初始化actor的完整随机Hurdle，经原F执行。续策不混入确定性Dirac；0/1.875秒只作为成对根动作。记录真实actor/F输入、atomic batch次序、分布参数、提案和执行动作、事前冻结snapshot及独立动作RNG。结构原子用合并preimage质量，连续部分用含F Jacobian的密度；目标变化后重新计算RN，同快照同输入才有精确c=1。原混合V/SAC backup、target子集/min、初始化、456更新、24000秒、物理基线和trust保持原合同。

固定容量为三线各一对、每臂前45个真实闭合事件（零时长逐行占槽），270槽加15普通槽。旧267普通名额保留15、替换252；旧18首动作名额保留6、取消12，共腾出264续事件名额。它们是新前缀的抽象权益，不是旧物理标签的授权。三对issue窗分别为7X 1200–1500、102X 6600–6900、705X 12000–12300秒；先保留前三包普通标签，各对随后占18包，57×5槽及57×8更新日历不变。每臂最多300原生秒，不足45、缺行、迟到或物理不可分离均保留失败，不按奖励追采、不以普通标签补齐。

完整链物理闭合后仍按五槽入库；根trace只能访问当时已入库的连续前缀，不能提前使用后包反馈。各线只有一个窗口，标签排队年龄可达6000秒；这是容量/支持先导设计，不能视为三线两窗的正式性能对照。45来自预留前三包后的270/6等分，不按旧奖励位置选定。

`budget_plan.py`给完整槽位替换、包日历与入库前缀；`behavior.py`实现执行分布评分；`run.py`只载入服务器原初始化actor，复用v39/v39r1已验证的三路target分布及Q子集证据，在v38旧真实链的前45事件上做支持压力诊断。旧行为仍是原确定性策略；拟议μ下的旧链评分不能证明新随机行为的实际奖励可达。奖励见证只在系数构造之后关联，不授权入训。

`launch.py stage/days/finalize/collect`只处理v40代码和最多24KB汇总。两个场景任务可并行，复用旧target结果省去三路模型重载/重算。执行门依次区分分布/预算可行、旧链压力诊断、新行为实际采集、训练效果；当前没有采集或训练提交路径。
