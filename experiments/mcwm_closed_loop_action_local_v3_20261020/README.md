**公交 MC-WM v3：执行动作一致化与线路局部校准的小规模对照**

新代码与输出只写本目录。旧冻结实验、v1、20261020 正式批和 v2 诊断批只读；直接使用服务器已有初始化、历史、source 数据及 v2 的 102 条 source 同车区间，不复制 checkpoint。

两个预先选定训练种子 6201/6202 × 稳定/限速场景 × 四个控制臂，共 16 个完整 24,000 秒开发日：`old_model` 复现旧 A2；`action_real` 使用统一执行动作和 0.75×观测 TD；`action_model` 加入 0.25×绝对 trust 加权模型 TD；`action_local` 再接入线路局部校准。其余初始化、全局反馈 285 条、57 包、456 次策略更新及 9,000 秒限速均相同。

新三臂统一使用 `a=F(s,u)`：actor Q、target Q、模型想象、trust bootstrap 与实际执行共享同一个可微动作规则。真实回放中的执行动作直接使用。熵和温度对应潜在提议策略 `u`；动作变换存在平台，未假定其执行动作密度仍是原策略密度。现有 canonical 状态截断车距，因此共享规则与原 raw-state v19 可能不同，实际分歧频率与 holding 差值逐场景统计；`old_model→action_model` 同时检验一致化后的完整控制链。

所有臂都独立接收同样 eligibility 的延迟同车区间反馈，维持 source 冻结、在线线性和线路 EMA 三个预测器。仅 `available_at<=18000` 的真实标签用于学习；策略不同导致的实际标签数量分别报告。局部预测相对 source 固定参考的每线路时长变化构成世界模型协变量；9 个系统、当前线路和执行 holding 交互特征通过无截距 ridge 回归修正原有四个全局输出。监督仍是实际全局 SMDP 的时间、成本和人数变化；同车区间时长不会替换全局步长。回归在零上下文时保持恒等，使用发出全局动作时保存的协变量，在延迟评分后拟合。模型臂也被动拟合、评分候选校准，只有局部臂将其用于 TD。

每包第一步保存同一实际模型样本、同一随机数下校准开关的模型时间/成本、TD 目标和损失差，以及预测后继状态引起的后继动作差。每包另在相同已到达状态上比较更新前后的提议与执行动作。最终判断同时查看先评分后拟合的预测误差、模型 TD、实际执行动作及稳定/冲击的绝对乘客成本。两个种子逐一报告，不能作为正式优越性确认；链路非零也不等于成本改善。

执行：`python3 launch.py stage` → `preflight` → 原生预检通过后 `submit` → `finalize` → 完成后 `collect`。预检仅推进约 4,200 秒、50 条全局反馈和 10 次策略更新，以覆盖真实局部反馈与 TD 连接。服务器保留 JSONL，最终仅收集小型 `pilot_summary.json`；不下载轨迹、CSV 或 checkpoint。下一批正式实验需根据这批开发证据再决定。

执行记录：19 项针对性测试通过，包含非零校准时诊断开关不改变更新的验证。原生预检任务 `t199128–t199130` 全部完成，均为 4,200 秒、50 条全局反馈、10 次更新，实际 1,350 秒执行限速，乘客账本平衡。完整开发日任务为 `t199133–t199148`；提交清单保存在本目录，固定预算后不按结果调参。

在读取完整成本结果前，额外固定 `18,300–24,000` 秒为停止更新后的持续性分析窗口：末次 18,000 秒截止的反馈可能晚几秒处理，因此逐项核对实际末次更新时间不晚于 18,300 秒。`holdout.py` 从服务器账本日志计算窗口增量，写新文件 `pilot_summary_with_holdout.json`，保留首次汇总；本地仅拉合并后的这一份小型 JSON。缺失端点保持缺失，不填零；相关验证通过，合计 20 项针对性测试通过。

首次汇总完成后执行 `python3 launch.py holdout`，再执行 `python3 launch.py collect`；收集命令仅下载合并后的 `pilot_summary_with_holdout.json`。
