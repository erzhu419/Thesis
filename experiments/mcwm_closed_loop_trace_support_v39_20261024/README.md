# v39：真实事件trace构造与支持预检

本轮只读复用v37r1三路冻结模型、v38真实事件链及原v37的285槽。目标backup仍是`r_scaled+0.1V+0.9SACα`，不训练、不新增原生前缀或分支，初始化、456次源更新、24000秒目标时长、F和trust均保持原值。

固定λ=0／1：0核验原生float32单步目标按位一致，1仅作构造和支持上界诊断，不根据12状态收益调λ。Qbar用前一步bootstrap的同target子集/min，在真实ns、因果memory_ns和下一记录执行动作上计算，保留原两动作批形状；full-head-min的差另计，不能替代。

原续策为确定性actor。先重建受干预首批其他车辆的nominal-prior策略输入，再精确核对其F后动作；目标π和F仍看真实记录状态。支持按实际Hurdle actor计算zero gate、F平坦区、显式positive clamp原子的并集质量。连续密度不能充当Dirac行为下的原子质量，普通浮点舍入格点不增加结构支持；未知行为输入和极小质量下溢分别报告。

两个数据范围分开：v38完整留出链只作诊断，所有反馈均不准入训练；原285槽按场景、前缀、分支、动作臂、完整TD及收据来源精确核对。267 ordinary只沿sequence、状态、记忆、时钟均连续的真实事件分组，不跨过未授权或零时长事件；18条paired首TD各自单独成链。训练配对的300秒等待／乘车聚合原本随两槽授权，但不能转换为未记录、未授权的中间TD或伪300秒状态。

`launch.py stage`只上传本目录；`continue_batch.py`提交稳定／冲击两个high任务，每个预留3 CPU，三路冻结模型实际并行评分。首条真实链预检直接复用到完整处理；两场景结束后自动汇总。事件级证明留服务器，只拉取不超过24KB的汇总。新增原生秒、训练槽和优化器更新均0，checkpoint不下载。

判断顺序是构造保真、执行支持、预算覆盖。即使算术和子集检查通过，支持在真实奖励前截断，或需要的TD超出285槽，也不进入训练。原生分支和训练均没有自动后续提交路径。
