# v59：当前续策下的预算内300秒动作差分

目标是让使用 dripping data 的控制方法在相同条件下，比不使用新结果监督的 MC-WM 降低实际乘客成本。本轮先验证成本差分读出是否值得进入控制试验；不要求每条线路、每个时窗都改善。

新外生种子106259、动作流526259；稳定/冲击各一个24000秒共同前缀。复用服务器 v54 中保存的真实 v53 μ14，冻结控制全部前缀和后缀，不重复其 warmup。三线各三个训练窗、两个停更后留出窗；每状态并行执行0/7.5秒两臂，记录真实300秒等待、乘车成本及完整合法事件链、动态记忆。首对预检复用同一前缀，不额外起日。

每场景9个训练对占18槽，替换普通反馈：267+18=285。两路新学习均从相同50000步初始化开始，57包×8步=456，保留参数和Adam。fresh 使用新结果；no_fresh 只读取独立的当前状态/动作/记忆文件，用完整历史转移替换结果监督。两路保持相同同步M8单步目标、原F、trust、采样器和特征，并实际并行。该数据流不同于 v53 的连续271条方案，不在断开的配对记录上训练trace。

沿用线路常数和原低维头距读出，ridge=1；仅拟合已入285槽的新训练对，不增加SGD。留出输入在主学习冻结后打开，真值仅由汇总使用。比较读出、fresh/no_fresh Q排序、固定0及固定7.5的方向、regret和等待/乘车分解。原模型、旧诊断真值与冻结结果保持只读。

若读出在完整独立留出上相对no_fresh-Q和固定0降低合计300秒选择成本，且稳定合计成本不增加，才考虑单独的小规模真实控制对照。300秒读出通过仍需以部署成本验证是否胜过MC-WM。原生与失败分支开销单列，缺失/不支持/零时长如实报告；不自动补跑或推进控制。
