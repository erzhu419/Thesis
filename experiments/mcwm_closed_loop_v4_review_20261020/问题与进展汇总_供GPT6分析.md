# 公交 MC-WM 在线闭环：问题与进展汇总

日期：2026-10-20。用途：给 GPT‑6 做原因分析与后续方案设计。本文包含必要背景、实际实现、已完成实验与关键数值；不要求接收者先阅读历史对话。

**核心问题。** 我们希望用历史目标数据和有偏简易仿真初始化，再用持续少量到达的 fresh target environment online data 校正当前运行机制，最终改善公交控制。现在数据确实滴入、模型确实更新、critic/actor也确实更新；同车区间预测能明显适应局部限速，但在线世界模型、上下文和局部读出没有形成稳定的额外控制收益，有些比较还更差。希望解释失败发生在哪一环，判断当前实现是否偏离了这个目标，以及下一步最有信息的修正是什么。

**先澄清“更坏”的参照。** 现有持续更新策略整体优于同初始化、不更新策略的行为参照；变差主要发生在“额外加世界模型/校准”的增量比较中。新目标数据与额外优化步数的独立贡献尚未隔离。因此不能把现象概括成“fresh target data 本身让控制普遍变坏”，也不能只用“更多数据不保证改善”结束分析。

## 1. 最初目标与本轮工作边界

第六章原冻结公交版本采用固定 target offline data 与 source 交互，目标训练新记录预算为0；冻结结果 `F-FINAL-225` 保持原样。我们在独立目录新增在线闭环，target 为 SUMO 公交系统，source 为简易公交仿真先验。它是仿真到仿真的研究，还不是实车部署。

原 roadmap 的核心结构是：

```text
历史目标数据 ─┐
简易仿真先验 ─┴→ 当前世界模型 → 后台策略更新 → 目标公交系统
                         ↑                       │
                   上下文/残差更新 ← 新完成且已到达的目标记录
                         ↑                       │
                         └──── 滚动事前预测评估 ─┘
```

目标不只是把新数据接进代码，而是让当前机制的校正变成更好的实际控制；普通在线残差/上下文先建立可靠起点，自动机制分解是否有额外价值另行验证。目前还没有完成自动结构学习，不能把现有线路局部读出称为已经验证的因果机制模型。

## 3. 当前实验协议：fresh data到底有多少、如何到达

- 同种子各臂使用同一份50,000步初始化；固定历史target记录32,768条，固定source记录4,096条。当前在线阶段复用这份source池，没有继续采集新source交互。
- 运行24,000仿真秒；稳定场景不干预，局部限速场景在9,000秒将同一路段速度降为原来的0.65，影响7X/102X/705X。学习器不接收一个显式的“现在发生了限速”输入。
- 全局反馈：1,200到18,000秒，每300秒释放一包5条不同的正时长、非终态记录，合计57包、285条；结果完成后至少延迟30秒才可用。每个窗口取最近可用的5条，其余原始事件记录不进入学习。
- 每包进行8次策略更新，共456次；世界模型每包对direct/residual两个候选各重拟合10步。事前预测先保存，结果到达先评分，再允许训练。
- 原始target环境产生的控制事件远多于285条；“环境有fresh数据”与“学习器使用全部在线数据”不是一回事。285是刻意限制的global监督预算。
- 另有独立物理区间流：source初始化102条，分线50/31/21；每个target控制日也完成102条真实同车区间。实际可用于学习的target区间stable为92条、shock为91条；其余因available_at超过18,000秒只评分。物理标签预算与global285条分开计算。
- 最后一次策略更新在18,000–18,004秒，停止更新窗口固定18,300–24,000秒。该窗口延续同一天的客流状态。

真实成本统一为 `(2×累计候车乘客秒 + 累计车内乘客秒)/全日出发乘客数`，包含尚未完成乘客已经累积的时间。各日全日出发乘客数均15,079，负的成本差表示改善。

## 4. global转移、物理区间与当前状态不是同一层次

**物理标签**是同line、vehicle、trip从上游站decision-ready到下一站decision-ready的完整区间，包含holding、运行/信号和下一站服务，不能称为纯行驶时间。

**global控制转移**在任意下一控制事件到来时关闭，可以从车辆A连接到车辆B；其正时长往往约1秒，不是当前车到下一站的几十秒。四个全局目标是：

\[
g=\big[\log(1+\Delta t),\ \log(1+(-r)),\ W'-W,\ O'-O\big],
\]

其中`r`为全系统该事件间隔内的负成本，W/O是系统等待/车内人数。当前canonical状态由5个global prefix与最多16×14个当前同时决策事件slots组成，含时钟、当前slot、系统人数及线路/站点/headway/队列/载客等；没有显式保存全车队未到站车辆的连续进度或当前路段速度因子。

世界模型输入为当前状态和当前单车执行holding，另外预测未来事件数、线路、站点、局部状态和邻接信息。当前local readout仅改四个global头，不改未来事件结构。以上是实现事实；是否构成关键部分可观测性/动作归因问题，仍需分析，不能直接认定原转移标签连接错误。

## 5. 当前实际学习链，而不是概念上“收到fresh就更新策略”

**5.1 真实回放与世界模型。** 新global记录进入容量285的recent池；因为总预算也为285，冲击前记录一直保留到实验结束，没有按最近5条覆盖。世界模型每次用累计recent加等量随机历史target记录，组成1:1数据集重拟合；direct/residual模型权重继承，但每次拟合重新建立Adam。source基模型冻结；normalizer从source建立一次后固定。两个家族按最近128条事前预测的六组损失均值选择。六组为global四头平均MSE、local、count、line、station、neighbor，并非直接按控制成本选择。

**5.2 物理预测与局部读出。** 目标同车区间先评分，再更新source+target ridge充分统计量，并用每线残差EMA（系数0.2）校正。三条线路在固定source参考输入上的预测偏移被压缩成3维delta，再展开9个系统/当前线路/执行holding交互特征。无截距、零初始化ridge将它映射到四个标准化global头。每包使用累计global标签及发出动作时保存的旧特征，针对刚更新的基础模型重新解算读出，没有遗忘。`action_model`也旁路拟合/评分候选读出，但只有`action_local`实际应用。旧A3的全局EMA偏置在v3/v4中关闭。

```text
fresh global labels → recent → 观察数据TD / value学习
                       └────→ global world refit
fresh same-car labels → 物理ridge+每线EMA → 3维delta → 9×4读出 ─┘
world + 当前策略F → 一步合成转移 → trust加权model TD → critic → 后续actor更新
当前canonical state → actor proposal → F → target实际执行
```

物理上下文没有直接输入actor/critic；没有MPC，也没有用物理预测直接替代执行holding。模型合成的next state不直接加入actor训练状态池；generate为no_grad，一步生成以selected recent里的真实状态为起点。

**5.3 实际批次不等于“32k旧样本淹没285新样本”。** batch size=256、source/target对半；target分区又半历史半fresh。每次更新实际为source128、历史target64、fresh target64，actor也使用这256个观察状态。因此fresh状态被过采样到25%，确实进入actor。代码中`scope="online"`实际指固定source池，fresh target在`recent`，变量名容易误导。

模型臂critic损失的分区系数为：

\[
L_Q=0.1875L_{history}+0.1875L_{fresh}+0.375L_{source}
 +0.25\,\mathbb E[w(s,a)\ell(Q,y_{model})].
\]

`real075`删除最后一项，其他系数相同；旧A1/real1的观察TD总系数为1。模型loss乘绝对trust后求均值，不除以trust总和，也不把总权重重归一。

critic的H2O+ target为：

\[
y=10^{-4}r+(1-d)\,[0.1V(s')+0.9\,SACsoft_{\pi,\bar Q}(s')].
\]

当前各类batch的discounts都为1，控制target没有额外gamma或`gamma^duration`；预测时长只经next-state clock影响bootstrap。V分支仍在history+fresh target分区继续更新，并未永久冻结。

actor优化观察状态上的熵正则Q目标，Q动作使用共享`F(s,u)`，熵仍是latent proposal熵。实际顺序为actor-before-critic，模型TD先影响本次critic，最早在后续actor更新通过Q间接传递，没有直接的model-TD actor梯度。

**5.4 trust也有自己的目标。** trust使用refit后当前recent训练误差，误差是上述六组预测loss的平均，不是物理区间MAE，也不是保存的事前预测误差。置信度`c=1/(1+error/tau)`，tau随误差中位数EMA更新；QDelta拟合`log(c)+0.9*QDelta_target(next)`，权重`w=exp(QDelta)`。这个0.9是trust折扣，不是控制Bellman折扣。其长期累计意义与密集global事件步长是否合适，尚未做针对性消融。

## 6. 已修正的真实问题：训练与执行动作曾不一致

旧链路部署为`a=F(s,u)`，真实回放/世界模型标签保存执行动作a；但actor objective、target Q、模型想象与trust使用原proposal u，优化的后续策略与部署不一致。

v3已让这些位置共享F，保留proposal熵；原两种子新三臂164,256次实际动作与原native规则没有超过1e-4秒的差异，最大3.24e-5秒。修复后原两种子冲击控制改善，但剩余三个种子未稳定延续。执行映射仍会将约30秒的平均proposal压缩成约8.7秒实际holding，物理动作压缩并未消失。

因此不能继续把旧动作错配当作当前未修复根因，也不能认为共享F就已证明控制更好。

## 9. 分头TD说明接通了什么，没有证明什么

原两种子shock后共62包、15,872个实际模型探针行全部应用校正。保持同起点、动作、解码/target随机数、critic/policy和实际trust，单独移除各头。下表是实际校正−移除变体的平均绝对差：

| 移除校正 | target Q差 | 未加权TD loss差 | trust×0.25后模型loss差 | 固定策略后继执行动作差，秒 |
|---|---:|---:|---:|---:|
| 全部四头 | 0.017239 | 0.003923 | 0.00014536 | 0.00004517 |
| 成本 | 0.016568 | 0.003716 | 0.00013978 | 0 |
| waiting | 0.010320 | 0.002491 | 0.00009403 | 0.00000411 |
| onboard | 0.004442 | 0.001035 | 0.00003875 | 0.00004311 |
| duration | 0.000294 | 0.000050 | 0.00000206 | 0.00000065 |

成本直接影响reward，等待/车内人数经bootstrap也有实质影响，某些阶段bootstrap还会反转reward项方向，不能只保留一个头的解释。成本头不改next state，所以固定策略后继动作探针的该项严格为0，不代表成本奖励不能通过critic训练改变最终策略。

shock后平均trust约0.173，名义0.25模型系数变成约0.0432的平均绝对系数；模型/真实TD梯度范数比约4.14%。局部校正TD扰动乘trust×0.25后约保留3.70%。这证明信号存在且较弱，不证明增加权重会变好。

这些是固定当前网络的同批诊断，不执行影子优化，单头差不可加和，不能唯一归因真实成本。实际`action_local−action_model`在原两种子shock全日为+8.808/+14.144秒，均+11.476；停更后窗+3.335/+0.341，均+1.838。stable全日反而均−5.275，停更后窗均−0.220且方向混合。

## 11. 请GPT‑6重点分析的问题

希望从“当前闭环是否正确表达研究目标”出发，区分实现缺陷、建模/目标选择、数据覆盖和优化问题，而非只建议增加数据、增加网络或扫超参数。
