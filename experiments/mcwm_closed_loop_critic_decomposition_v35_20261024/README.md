只读复用 v34 服务器上四个冻结模型、12 个已保存 issue 状态及 v33 原 285 条反馈，不调用重建、训练、SUMO 或分支。F、trust、actor/V 与参数不改。每场景一个 high CPU 任务，完成后自动 high 汇总；仅拉取 ≤20 KB JSON，模型、全矩阵及原事实留服务器。

对两个已执行动作逐头拆出 memory-trained base、记忆水平项和动作交互。固定权重比较 base（删记忆）、level-only、action-only、full，并保留独立训练的 zero_memory 对照。每个变体记录两动作的 min-head、逐头动作差分、min/mean 优势、固定低动作胜出头的差分及换头项。full 与 zero 必须精确复现 v34 保存的 min/mean-Q 和选择；native float32 加法顺序单列。水平项对同一头的动作差分为零，但可重排各头的最小值，不能把 full-minus-base 的 min-Q 差全部归给动作交互。

旧事实只统计实际执行 holding：分线路、原训练窗及两个 v34 窗口报告数量、分位数、范围、0/1.875 秒附近（预声明 ±0.5 秒）、60 秒 floor 与低动作覆盖。每个新 issue 对比同线全期、9000–12000、12000–18000 的动作范围、距离和记忆逐列范围。source/history 的零记忆不作为非零记忆动作交互的支持。小 SVD 描述实际残差设计 [m,z*m] 的秩，保留常数 presence 对动作斜率的贡献；冗余特征导致秩低不等于机制不可学，也不按该值选择模型。小汇总显示7位有效数字，精确值与复现检查留服务器。

真值仅在最终分析时与冻结结果相连，不参与选点、拟合、采样或阈值调整。先查 early 三处大错是 base 已有偏斜还是直接记忆作用，再查 tail 两处翻号是否涉及水平项重排 min-head。根据实际分解限定一个 critic 候选改动；本版不部署改动，不推进独立确认。
