**公交 MC-WM v4：四个全局输出诊断与剩余固定种子稳定性验证。**

本版只增加被动观测，沿用 v3 的统一执行动作、局部区间学习器、9协变量全局读出及训练设置；不调整控制或模型TD权重。原冻结实验、正式批以及v2/v3代码与结果只读。直接读取服务器已有输入，不复制checkpoint或重新采集source。

固定20个24,000秒开发日：6201/6202的模型与局部臂×稳定/限速，8项精确复现并补齐诊断；6203–6205的0.75真实TD与模型臂×两场景，12项补足稳定性。原两个种子、剩余三个种子及五种子合并结果分别报告，属于开发证据。各项均285条全局反馈、456次策略更新，source及同车区间资格/延迟预算保持v3一致。停止更新后的窗口固定为18,300–24,000秒，并核对实际末次更新时间。

每条选中全局标签先评分后拟合：分别保存时间、成本、等待人数增量和车上人数增量的有符号误差、MAE/MSE，区分标准化值、原始物理值及实际解码值。保存发出动作时的线路、站点、局部参考/在线/EMA变化和逐特征校正贡献，按阶段与受影响线路分组；额外统计已有解码器的饱和情况。

每包首步在同一真实生成批次上，对整个校准及四个输出逐一移除。保持执行动作、解码与target随机数、critic、policy和实际trust权重一致，记录奖励、bootstrap、target Q、加权TD loss及预测后继动作的变化。现有target不以预测时长改变折扣：时间输出经后继状态时钟作用，成本输出直接改变奖励，两个人数输出经后继状态作用。这些探针不执行影子优化，也不作为可加的控制因果分解。

额外观测不改变训练、数据或随机数路径；单元测试和6201/6202八项成本精确复现检查用于确认。全部运行结束后服务器聚合，先报告各输出的偏差方向和阶段变化，再决定如何修正全局映射，期间不据结果调参。

`python3 launch.py stage` → `preflight` → 原生预检通过后 `submit` → `finalize` → 完成后 `collect`。两个预检分别覆盖局部启用6201与被动模型6203，推进约4,200秒、50条全局反馈、10次更新。只收集必要的 `head_diagnostic_summary.json`，详细JSONL留在服务器，不拉CSV、轨迹或checkpoint。
