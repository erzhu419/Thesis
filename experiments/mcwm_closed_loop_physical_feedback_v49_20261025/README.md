# v49：285槽内的单事实流物理覆盖方案

结果与下一步见 [decision.md](decision.md)。本版只做设计和旧主日结构预检，不包含采集器、训练入口或新增原生分支。

**计数与真实端点。** 保留15条新普通反馈及24次warmup更新，随后保存实际μ24。新主日从9000秒后首个真实issue开始，保留恰好270条相邻原生TD，零时长也逐条计槽。需要271个真实issue界定270个闭合；第271个issue是已观察、尚未执行的公共端点。三线各取窗口[9000,9300)内首个issue作根，引用同池中的后继，不重复计标签。每槽含一个真实TD的s/a/ns、奖励、dt、因果memory_s/ns和行为上下文，不改为积分块或稀疏跳链。

**行为与校正。** 全程用完整随机μ24经原F执行，不在流内强制0/1.875秒动作。逐issue记录实际actor/F输入、gate/mean/std、提案、执行动作、快照和独立行动RNG序号。未来目标π的校正必须覆盖每个原生后继，原子质量与连续密度分别计算；不能把μ自比c=1当作训后π的权重。某根的首动作不乘该根的续策比，但它若是更早根的后继，仍须乘对应比率。保留原混合backup、每链接0.9及同target子集/min；本版不安装新目标。

**入库与失败。** 公共端点须不晚于9600，各根至端点均至少300真实秒；反馈延迟30秒，在9630先入库全部270条再执行432更新，总285槽/456更新。未来目标对照共用初始化、同流、入库日历及Adam连续状态。缺线、270条不足300秒、迟到都失败，不改起点、不扩标签、不补旧记录。270后至9600的时间投影只作容量诊断。

`protocol.json`在预检前固定方案；`plan.py`提供纯函数 `build_plan()` / `precheck_issues()`；`run.py`在服务器投影v43主日时间/线路/行为字段，重算原F和记录μ自比测度。原乘客账本未转交设计函数，旧留出未使用。六项聚焦测试覆盖计槽共享、零时长、短缺、真实超时端点、迟到与禁止挪起点；入口为 `python3 -m unittest experiments.mcwm_closed_loop_physical_feedback_v49_20261025.test_plan`。

服务器生成 `budget_plan.json`、各场景完整时间投影及 `summary.json`；本地仅收11,091B汇总。`cutoff_bounds.json`从该汇总推导公共末端的c=1上界，无额外数据读取。high任务定义和提交失败保留；执行与调度限制见结果说明。原冻结实验、旧代码及已有结果均只读。
