# MC-WM最终采用版本：图F-2

2026-10-12确认采用本批结果，Git定稿标签为`mcwm-f2-final-20261012`。论文版本登记为`F-FINAL-225`。

本批采用重新对齐源环境生成规则及需求轮换的MC-WM续训策略，与保留的完整H2O+及纯源SAC策略比较。它不是早期`v13`的20次初始化源偏差实验，也不是车头时距奖励的`v19`补充实验。

## 采用的代码和设置

- [训练入口](train_mcwm.py)：复用对应初始化编号的50000次IQL离线初始化，再进行20000次续训；名义源交互预算25000个事件。
- [完整协议](protocol.json)：MC-WM环境经验损失系数0.75、模型项系数0.25，使用归一化置信递推；不启用旧源机制拦截。
- [训练记录](training_summary.json)：五次新增续训的实际事件数、更新次数和需求覆盖。
- [评价入口](evaluate.py)及[场景生成](prepare_scenarios.py)：单驻站动作、乘客广义时间奖励，统一使用`quarter-load-sixty`完成保障，附加驻站缩放为1；每回合24000秒。
- 训练算法继承[mcwm_seed_confirmation_v13/run.py](../../experiments/mcwm_seed_confirmation_v13/run.py)及其在本仓库中的辅助实现；本批应调用`train_mcwm.py`，而不是直接重跑旧v13入口。
- [MC-WM运行代码快照](../../experiments/mcwm_bus/runtime/MC-WM/)与[H2O+公交运行代码快照](../../experiments/mcwm_bus/runtime/H2Oplus/)已在本仓库保留，原训练派发记录指定这两处运行代码。

源需求轮换规定为0.75、1.00、1.25，但在这批事件预算内各训练只进入前两档。测试覆盖全部三档需求，源训练实际覆盖与目标评价条件分别记录。

## 数据和结果

三种控制器、五次训练初始化、五个新环境块、三档目标需求，共225回合。

| 控制器 | 人均广义时间/秒 | 行程完成率/% |
| --- | ---: | ---: |
| 对齐续训MC-WM | 2360.49 | 96.8445 |
| 完整H2O+ | 2383.51 | 96.6864 |
| 同执行规则纯源SAC | 2400.74 | 96.5819 |

MC-WM相对H2O+与纯源SAC的平均人均成本分别减少23.02和40.25秒，完成率分别提高0.1581和0.2626个百分点。

## 适用范围与重跑条件

这是完整控制器比较，不是计算量相同的世界模型单因素消融。MC-WM相对H2O+的五初始化配对95%区间包含零；相对纯源SAC的区间低于零。均值改善与稳定优势分别理解。
