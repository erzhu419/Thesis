# v11 响应残差与原生配对诊断

固定 300 秒端点的时长直接取 300，仅拟合等待、乘车成本残差。同车端点以固定源域物理预测的非 holding 时长加实际 holding 为时长基线，各端点的成本基线使用动作发出时全局等待、在车人数。保留原 58 列和 v10 直接拟合模型，同一新轨迹、同一批标签比较；这些读出不参与执行，trust 保持原规则。

主实验为 6201/6202 × 稳定/局部降速，4 日各 24000 秒，沿用 50000 步初始化、32768 历史行、4096 源域行、固定 102 个物理源样本。每日日志预算 57 包 × 5 = 285 个训练 issue，456 次策略/trust 更新，最后期限 18000 秒。记录最后一包实际处理时间；完成后所有参数冻结，各线路独立争取前两个共同可执行的 0/7.5 秒诊断事件，缺失如实保留。

先运行短日原生预检和低/高两条 300 秒分支，通过后运行四日。随后只取种子 6201 两场景各线路首个停更后状态：6 个状态、12 个原生分支，比较真实下一全局事件、同车下一站及固定 300 秒成本差。每条分支从相同初始模型和外生种子完整重放新共同前缀，逐项比较原始/规范状态、全局乘客账本、训练记录和旧/新预测；仅替换一个动作，后缀零训练、无新校准干预，原生时钟精确截在 +300 秒。同车端点超出截点则缺失。

新增分支预算为 3600 后缀秒，重复前缀时长与重放训练名额另计，不混作新训练标签；预检计算也单列。所有调度任务为 high。服务器仅回传小型 gate 与最终汇总，不拉模型和原始轨迹。旧代码、冻结实验及已有结果不改。

入口：`launch.py stage`、`launch.py preflight`，随后 `continue_batch.py` 按 gate 推进到小规模诊断汇总。独立确认不自动提交；依据分线路覆盖、匹配预测误差、解析前虚假即时收益、配对成本收益方向和决策 regret 再决定。
