# v38：真实多事件信用诊断

本轮只定位300秒损益进入原生奖励和bootstrap的时点，再据此限定一个目标改动。复用服务器 v37r1 的 zero_memory、per_head_level、shared_level 冻结模型，不训练、不回灌真值，旧代码和结果保留。

服务器实查：v37两场景共52个后缀均有首转移和精确300秒账本，但52份suffix trace都是空文件，没有完整事件／记忆链。因此需新增原生采集，审计见 `existing_log_audit.json`。

- 先精确复现三路冻结模型的旧4状态预测、组件和CRN目标。原生前缀沿用原50000步初始化控制器、外生种子106237、24000秒目标时长和统一F。
- 每场景三线各取两个状态：早窗固定原v37状态，较晚窗固定为 **[19200,19500)**；只按issue时F、停站和actionStepLength可行性选首个状态。原生不可达如实缺失。
- 同前缀0／1.875秒双臂实际并行。完整记录真实全局转移、因果记忆和每秒乘客账本；复核旧早窗首转移与300秒真值完全一致。首对预检在正式采集中复用。
- 精确300秒只结算账本。继续到其后首个真实非终止控制事件，闭合上一转移，但不执行端点动作。最长延长120秒；无端点则保留缺失和未标注区间。
- 分线路、稳定／冲击及两窗口拆分等待、乘车、奖励、V、SAC-Q、熵、target lag和续策差。语义事件按车辆／站点／出现次序匹配，异步时钟单列；零时长与固定300秒账本单列。

原目标为 `r_scaled + b(ns)`，其中 `b=0.1V+0.9SACα`、`r_scaled=1e-4*r`。真实链的 `Σr_scaled+b(T)` 是共同续策下的诊断量，不能直接视为原混合Bellman算子的多步训练目标。用

`q0 = Σr_scaled + b_last + Σ(b_i-q_(i+1)) − Σ(target_i-q_i) + Σ浮点加法舍入`

核对信用账，续策差另拆为混合backup与实际动作target-Q之差、target lag；不把300秒损益直接覆盖长期Q。

冻结模型仍来自每场景285槽、456次更新；本轮新增标签槽和更新均为0。新增诊断上限：2条完整前缀48000原生秒，12状态24后缀固定7200秒，加真实端点延长最多2880秒；实际延长、失败前缀及缺失另记。前缀、后缀、评分均不训练，F、trust、采样器和物理基线保持原值。

`launch.py stage` 只上传本目录；`continue_batch.py` 提交两个CPU=2、priority=high场景任务，全部结束后提交服务器汇总。仅拉取不超过24KB的汇总，事件流和模型留服务器。旧预测或原生复现失败时保留失败证据与已消费开销，不能宣称完整诊断通过。

决策门：先通过复现、覆盖、执行、因果记忆及零训练检查，再比较物理损益首次出现、真实奖励首次出现与bootstrap变化。结果出来前不启动新训练或独立确认。
